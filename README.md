# 信息科技互动课堂 · 三课独立站

面向 **2024 人教版初中信息科技** 的学生课堂互动网站：

- 七年级第一单元：第 1 课《互联网发展靠创新》7 站、第 2 课《互联网应用新特征》6 站
- 八年级上册第二单元：第 9 课《互联协议仍沿用》6 站

三课独立，开始页任选一课；顶栏可在三课间随时切换。八年级内容接在七年级课程之后。

- 纯静态网页：无需安装、无需联网、无需服务器
- 适合投影 / 触控一体机 / 学生平板 / 手机
- 4 支小队实时累计“探索值”，完成挑战解锁徽章
- **每课各自顺序解锁**：每课完成上一站，才进入下一站
- **三课之间没有前置锁**；进度分别保存
- API 请求、HTTP 交换、轮询负载全部离线模拟，不访问真实网络

## 长期固定链接（电脑关机也能打开）

现在页面里的 `trycloudflare.com` 链接由**这台电脑**上的本地服务器 + 临时隧道提供；电脑关机、休眠或断网后就会失效。

要让链接长期有效，必须把整个网站放到**外部静态托管**：

1. **Netlify Drop**：登录后选择手动部署，把压缩包解压后的整个文件夹拖进去，得到 `*.netlify.app` 固定网址。
2. **GitHub Pages**：新建仓库，上传 `index.html`、`compat.html`、`assets/`、`README.md`，在 Settings → Pages 中选择从主分支根目录发布。
3. **学校网站服务器**：把解压后的文件放进网站目录，入口为 `index.html`。
4. **Surge.sh**：安装 Surge CLI，执行 `surge 解压后的目录`，可得到 `*.surge.sh` 固定网址。

> 静态托管不需要数据库或后端；上传后电脑关机也不影响访问。整个站点约 19 MB，图片和所有互动都在本地文件中。

## 第一课 7 个互动站点

### 01 网之初
- 点击球网、渔网、蜘蛛网，解锁“节点 + 连线 = 网络”的观察。
- 在组网板上依次点击两台设备拉线，把服务器、两台电脑、学习平板、手机连成一张网。
- 网络连通后可发送数据包，观察数据沿线路逐跳传输。
- 设计意图：从生活原型抽象出“节点、通信线路、资源共享”。

### 02 时光轴
- 把 A/B/C/D 四张事件卡放入 1981、1983、1989、2017 四个年份。
- 四个阶段页签：诞生 → 形成 → 互联 → 高速网络。
- 快速判断题：中国哪一年全功能接入国际互联网。
- 设计意图：用“关键事件”串起互联网发展逻辑，而不是死记年份。

### 03 结构室
- 星型 / 环型 / 网状三种拓扑一键切换。
- 点击线路可切断，点击星型中心可模拟宕机，再发送数据包观察是否还能送达。
- 健壮度仪表实时显示三种结构的差异。
- 设计意图：理解“多条路径 = 冗余 = 健壮”。

### 04 中国答卷
- 年份驾驶舱：1987 / 1994 / 1995 / 2008 / 2013 / 2023。
- 2008 与 2023 网民规模对比条。
- 全球互联网市值 TOP30 中的中国 8 家、5G“空白—跟随—突破—并跑—领跑”接力。
- 设计意图：从“接入世界”到“网络大国”，建立时间线与国家成就的连接。

### 05 互联网+
- 六个应用卡与“吃、穿、住、行、学、医”六个场景配对。
- 创意墙：学生写下校园/生活中的“互联网+”点子，选择领域后上墙，可点赞。
- 设计意图：从“知道应用”走向“提出自己的应用”。

### 06 北斗任务
- 点击“启动卫星定位”，三颗卫星回传距离，生成三个定位环。
- 学生点击三环交点，完成配送目的地定位；偏差会给出提示。
- 翻转“网约车 / 网购 / 外卖”应用卡，理解北斗在其中的作用。
- 设计意图：用可视化方式理解“三球交会定位”的简化模型。

### 07 闯关
- 8 道单选题，覆盖网络定义、四阶段、拓扑、中国数据、5G、北斗、互联网+。
- 答题即时反馈与解析；结束显示正确率、小队排行榜、徽章。
- 课堂回声：学会了吗 / 还想知道什么 / 想做的创新。
- 设计意图：形成性评价 + 课堂收束。

## 八年级第9课 6 个互动站点

![八年级第9课开场](preview/31-g8-intro.png)

### 01 数据接力
- 顶部展示智能音箱、手机、手表、汽车导航 4 张真实设备照片。
- 8 条数据卡：天气预报、实时路况、新闻推送、在线音乐；室内温度、心率、GPS、电量。
- 点数据，再点“互联网 / 云端”或“设备 / 卫星自采”来源框；放对进入来源清单。
- 设计意图：分清“互联网提供的数据”与“传感器直接采集的数据”，为 API 取数做铺垫。

![八年级第9课 01 数据接力](preview/32-g8-data.png)

### 02 API 取数
- 选天气接口、选北京，点击“发送 API 请求”；右侧返回 JSON：`temp`、`humidity`、`wind` 等字段。
- 从返回 JSON 中点出温度、湿度、风力 3 个观测字段；点 `city`/`updated` 会提示“不是观测值”。
- 全程离线模拟，不访问真实服务器。
- 设计意图：理解 API 是服务器提供给外部程序的取数接口，设备只取自己需要的字段。

![八年级第9课 02 API 取数](preview/33-g8-api.png)

### 03 HTTP 快线
- 组请求：`GET /v1/weather?city=beijing HTTP/1.1`；点击发送，观察请求包从设备到服务器。
- 再按“设备发出请求 → 服务器处理 → 服务器返回响应”的顺序点击三步。
- 请求错误时返回 404，提示检查方法、路径和参数。
- 设计意图：把抽象的 HTTP 交换拆成看得见的“请求—处理—响应”。

![八年级第9课 03 HTTP 快线](preview/34-g8-http.png)

### 04 负载实验
- 选择 20 / 200 / 500 台设备，轮询间隔 1 / 5 / 30 秒，运行 10 秒实验。
- 仪表显示请求次数、服务器负载、设备能耗；日志模拟设备不断询问“有新的指令吗？”。
- 运行后从 5 张卡中找出 3 个真实瓶颈：占用设备资源、能耗增加、服务器与网络负担。
- 设计意图：用数据感受 HTTP 轮询在物联网中的局限，而不是背结论。

### 八年级第9课：数据来源
- 互联网 / 云端：天气预报、实时路况、新闻推送、在线音乐。
- 设备 / 卫星自采：室内温度、心率、GPS 位置、剩余电量。
- 追问：哪些数据必须联网才有？哪些数据设备自己就能测？

### 八年级第9课：API 与 HTTP
- 天气 API 请求：`GET https://api.weather.cn/v1/now?city=beijing`。
- 3 个观测字段：`temp`（温度）、`humidity`（湿度）、`wind`（风力）。
- `city` 是查询条件，`updated` 是更新时间，不是设备要读的观测值。
- HTTP 三步：设备发出请求 → 服务器处理请求 → 服务器返回响应。
- 正确请求行：`GET /v1/weather?city=beijing HTTP/1.1`。

### 八年级第9课：HTTP 的局限
- 500 台设备 × 每 1 秒 1 次 × 10 秒 = 约 5000 次请求。
- 三个瓶颈：占用设备有限资源、设备能耗增加、服务器与传输网络负担加重。
- 结论：HTTP 在传统互联网应用中很出色，但物联场景需要更轻、更省、更快的通信方式。

### 八年级第9课：物联协议四要求
| 要求 | 场景 |
|---|---|
| 低功耗 | 智能水表：电池供电，装一次用 5 年 |
| 低带宽 | 农田传感器：窄带网络，只传少量土壤数据 |
| 低延时 | 工业机械臂：检测到人，毫秒级停下 |
| 兼容性 | 多品牌家居：不同厂商的灯、锁、空调联动 |

### 八年级第9课：协议决策
- 3 道判断题答案：HTTP；API；“画面更清晰”不是 HTTP 的瓶颈。
- 校园智慧农场：选 **物联协议**，理由选 **低功耗 + 低带宽**。
- 追问：HTTP 仍沿用在哪些环节？哪些环节必须换更适合设备的协议？
